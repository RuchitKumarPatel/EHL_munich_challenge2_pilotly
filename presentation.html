Objective

The trade-off we chose

We minimise est. input-token spend, priced cache-aware, subject to a bound on process friction — because that is the only outcome this export supports: there is no usage field, so tokens are estimated (chars/4), no public price sheet applies to anonymised model ids, so dollars are an assumption, and there are no quality labels, so friction means tool-call exit codes, not answer quality. Logged bill under the assumed default sheet: $412.95 over 1,000 trajectories and 10,845 billed prefixes — but the three sheets we priced spread by 1.78x, so read the ratio, never the dollar.

The signal

What the router looks at

Structure in the traces

The tools block — available before a single token is generated. bash / file_read / file_edit / file_write marks the claude lane (755 runs); apply_patch / shell_command marks the gpt lane (245 runs). Perfect separation, zero exceptions — so a cross-family reroute changes the tool contract, not just the price, and we refuse it. That gate alone puts 41.0% of est. tokens out of reach, leaving 675 routable trajectories.

Honesty

The off-policy estimate — and where it breaks

  • Method — Stratified reweighting across 33 strata over 778 job clusters — bounds, never points. Plain IPS returns 2.9599 for a quantity that must lie in [0, 1], so it has no effective sample to lean on. We report Manski bounds instead: the friction cost of rerouting 119 trajectories is at most +0.76 pp (0.48 pp identified + 0.28 pp widening for the 0.28% of spend with no support). No LLM judge was used.
  • Cache trap — 92.0% of the re-metered bill is cache reads — inferred from item-level prefix overlap, because the export carries no cached_tokens. A model switch resets that prefix, so every rerouted trajectory is repriced paying full write cost for its whole history. That is why the token gap (14.79x) and the dollar gap (2.83x) are different numbers.
  • Weakest point — The router does not beat randomising between two arms. At the same spend the single-arm mixture frontier reaches -3.83 pp while the gated router reaches +0.76 pp — a gap of +4.59 pp the wrong way. On these bounds the routing logic has not earned its complexity.
Close

At equal spend, one cheap arm beats our router. That negative result is the finding.

+4.59 pp — the gap, in the wrong direction

Weakness — no point estimate exists and none is coming: the MDE on the best-powered arm pair is 11.4 pp, so every contrast above is an upper bound. Tokens are estimated, dollars rest on an assumed price sheet (spread 1.78x), and the outcome is process friction, not answer quality — so the sign of any saving is not established from this export alone. Next step — either find a gate that clears the mixture hull, or ship the cheap single arm and say plainly that the router was not worth it.
